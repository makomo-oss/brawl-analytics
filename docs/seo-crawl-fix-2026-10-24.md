# 2026-10-24: BAN・ピックの初期HTMLとクロール導線の修正

10/24のURL検査で `/companion` がソフト404・未登録になっていた。HTTPは200で取得許可も正常だったが、初期HTMLは空のカテゴリから始まり、実際のモード・マップはブラウザーのAPI取得に依存していた。Google取得済みHTMLは閲覧できず、これがソフト404の原因とは断定していない。

## 変更

- BAN・ピックの既存画面をクライアントビューに分離し、Nextの静的HTMLとPagesの動的HTMLの両方に、正常な実データのカテゴリ・初期選択を渡す。ビルドには既存のガチバトル集計にあるモード／マップ対応を利用する。
- Pagesはカテゴリを5分ごとに再検証。正常なビルドHTML／JSONと最後の正常HTMLをフォールバックに使い、API障害・空配列・不整合な対応表で置換しない。正常データが一切ない場合は503にし、空の200を返さない。
- ブラウザー側も無効なカテゴリへの置換を防止。背景更新の失敗時も既存フォームを使え、BAN／Pick中は選択を自動変更しない。既存のSelect、チーム切替、計算、ドラフト順序を維持。
- ホームとキャラ一覧の既存コンテンツ下に、モード・マップ一覧への通常リンクを追加。ピック初期設定にも一覧・現在のモードランキングへのリンク、モード・マップ詳細にもピックツールへのリンクを設ける。新しい説明文・攻略記事・大きな入口カードは追加しない。
- モード・マップ詳細の再検証を、全カテゴリの掲載対象を走査する一覧更新から分離。最後の完全な掲載一覧／ビルド一覧を参照して、当該モード／マップのスコープだけを取得する。代表モードの更新に必要な公開API要求は4件以下。一覧・サイトマップの共通掲載対象と、既存の低サンプルnoindex条件は維持。

## 公開前の検証

- 公開APIを指定した本番ビルド、Next／edgeの型検証に成功。ローカル検証用に既存の正常集計スナップショットを利用。公開時の既存ビルド手順は変更していない。
- `test:live-companion`: 初期データ入りHTML、APIを待たない初回応答、再ビルドなしのカテゴリ更新、API停止・空配列・不整合データの保持、HTMLがない場合のJSONフォールバック、正常データがない場合の503、canonical・robots・HEAD／308／405に成功。
- `test:condition-pages`: 一覧API停止時も詳細が更新でき、無関係なスコープを走査しないこと、掲載一覧・サイトマップの収束、低サンプルnoindex、新しいマップと404に成功。
- 既存の `test:live-overview`、`test:live-brawlers`、`test:runtime-navigation`、`test:draft-data`、`test:public-stats-cache` に成功。
- 変更した配信処理・新規データ検証・スクリプトのESLintに成功。`edge/app.tsx` を含めた実行では、変更前からある69行目の `react-hooks/set-state-in-effect` エラーと137行目の依存警告が残る（変更前のHEADにも同じ処理を確認）。今回の修正では既存ナビの状態管理を変更していない。

- ローカルHTTP監査は掲載187 URLすべて200。固有title・h1・自己canonical、noindex混入なし、内部リンク先エラーなし。根拠はGit対象外 `frontend/.seo-data/seo-audit-fix-local-2026-10-24.json`。

## 公開後の確認

GitHub mainへのpushによる既存自動デプロイを使用し、本番HTML・リンク・操作を確認する。公開commitと本番監査結果はローカル `docs/seo-weekly-results.md` に記録する。Search Consoleへの登録リクエスト・サイトマップ送信は行わず、既存の週次評価で再クロール後の判定を追う。今回の公開確認と、Googleによるソフト404解消／再登録は別に扱う。
