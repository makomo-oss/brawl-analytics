# ドラフト開始の待ち時間改善（2026-10-05）

## 変更

- 設定画面で有効なモード・マップが選ばれたら、150ms後にその条件だけ先読みする。変更中の一時的な組み合わせは先読みしない。
- BANはマップスコアのみ使用しているため、開始時には対面・シナジー行列とモード統計の完了を待たない。軽量な同条件のマップ統計で開始する。
- Pickに必要な詳細統計は並列で取得し、揃ってからモードスコアを付与する。取得中・失敗時に未取得の相性を中立値として推薦しない。
- 失敗時はBAN内容を保持して再試行できる。リセット・アンマウント後の古い要求は画面に適用しない。
- 既存の公開統計キャッシュ（5分、上限32件、同一要求の重複防止、独立コピー）を利用する。集計式・マップ条件・推薦の重みは変更していない。

## 確認

- `npm run test:draft-data`: 対面取得を保留してもBAN用データが完了すること、先読みと開始の通信重複防止、完全な相性・モードデータの結合、条件分離、コピーの独立性、503後の再試行、空の相性応答ではPickを有効にしないことを確認。
- `npm run test:public-stats-cache`: 既存のキャッシュ契約を確認。
- 本番ビルド・型チェック成功。
- ローカルの実APIプロキシで相性応答を保留したままBAN画面の表示と6BANを確認。Pickでは手動選択を無効化し、読み込み中を表示。保留を解除すると相性推薦と手動Pickが復帰し、6Pickと完成編成の表示まで確認。
- 詳細要求を503にした場合もBANが開始でき、Pickで再試行を表示。復旧後にBAN内容を保持したままPickが再開できることを確認。
- 詳細取得を保留したままリセットでき、旧要求の到着後も設定画面と再開ボタンを維持することを確認。

## 計測と限界

公開APIの同条件（賞金稼ぎ・Dry Season、93キャラ、キャッシュが温まった状態）の単回測定:

|応答|時間|未圧縮容量|
|---|---:|---:|
|マップ統計のみ|223ms|40,411バイト|
|対面・シナジーを含むマップ統計|526ms|94,144バイト|

平均値・コールドキャッシュの性能保証ではない。ブラウザ計測はクリックからアクセシビリティ状態取得までの操作時間を含む。最初の未取得条件では軽量統計の通信待ちは残る。重い相性統計自体のSQL・計算処理は変更しておらず、Pickに進むまでに未完了の場合はそこで待つ。
