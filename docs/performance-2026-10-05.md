# 表示・読み込み速度の改善（2026-10-05）

## 改善前の計測

同じ端末から本番URLを順番に2回取得。キャッシュを消さず、HTML本文の取得完了まで測定。

| ページ | 1回目 | 2回目 |
| --- | ---: | ---: |
| ホーム | 882ms | 81ms |
| Tier表 | 220ms | 117ms |
| アンバー詳細 | 25,586ms | 121ms |

初回と再訪の差から、キャラ詳細の同期的な統計取得・再生成を優先して改善した。計測は各2回のみで、全利用者の平均値ではない。

## 実装

- キャラ一覧・詳細・サイトマップの期限切れキャッシュは直ちに返し、25秒以内のバックグラウンド処理で更新する。
- キャッシュがない既存キャラは、ビルド時に取得した実統計から同じWorkerレンダラーでHTMLを返す。取得日時・サンプル判定・canonical・構造化データを維持する。スナップショットは最新キャッシュ扱いせず、裏側で更新する。
- 新キャラにはビルドスナップショットがなくても、従来のライブAPIからURLを生成する。存在しないURLの404はキャッシュしない。
- Tier表の初期取得は5つのコホート・ランクから、選択中の1つに限定。カテゴリ取得もガチバトル選択時に限定する。
- 公開統計のみ5分の有効期限・最大32件の共有キャッシュを使い、同時リクエストをまとめる。失敗は保存せず再試行可能にする。ピック支援の加工でキャッシュが変わらないよう、戻り値はコピーする。プレイヤー検索・同期は対象外。
- デスクトップナビゲーションは既存のスタイルを保ち、使っていないドロップダウン機構を外す。スクロール位置はrefで保持し、1フレーム1回の処理にする。
- Tier表・ホームのキャラカード画像はブラウザーによる遅延読込・非同期デコードを使用する。

キャラ詳細の非圧縮JavaScript容量は385,019 bytes → 247,104 bytes（35.8%削減）。ページ全体の転送量や実際の描画時間とは異なる指標。

## 検証

- `npm run build`: Worker型検査、Next.js型検査、122ルート生成、107キャラと一覧のスナップショット生成に成功。
- `test:live-brawlers`: API応答を止めてもキャッシュ・ビルド実データから100ms以内に返ること、更新後のサンプル判定、新キャラURL・サイトマップ・HEAD・404/503・canonicalを検証。
- `test:public-stats-cache`: 同時取得、クエリ順序、TTL、失敗後の再試行、コピーの独立性、プレイヤーURL除外を検証。
- `test:brawler-preview-link`: クロール可能なリンクと従来のプレビュー動作を検証。
- ローカルブラウザー: 全体Tier、ガチバトルへの切り替え、ランク条件、アンバーのプレビューと詳細へのリンクを確認。

## 制約

初回応答に含まれる統計は保存時点の実データで、最新値はバックグラウンド更新後の次の表示で反映される。API障害中も保存データを表示するため、画面の集計日時を保持する。ビルドに存在しない新キャラを初めて開く場合はライブAPIの応答が必要。検索順位・利用者全体のCore Web Vitals改善を、この局所計測だけで断定しない。
