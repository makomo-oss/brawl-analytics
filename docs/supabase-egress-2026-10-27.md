# Supabase転送量の削減（2026-10-27）

更新スケジュール、60日間の分析対象、ランク条件、重複排除、時間による重み付けは維持する。

## 変更内容

- 通常のランク集計は `player_tag` と `unlocked_characters->ranked_rank` のみ取得する。キャラ一覧JSONはDB内に保持する。
- 明示的に `match_df` を渡してプロフィール自動再同期を要求する既存の呼び出しは、鮮度判定用メタデータを引き続き取得する。通常の日次集計ではこの経路を使わない。
- 対戦履歴は集計に使う11列を明示して取得し、未使用の `collected_at` を送信しない。ページ順・件数・期間フィルターは変更しない。
- 手動プレイヤー同期、ランク補完保存、期限切れ履歴削除では `returning="minimal"` を指定する。結果データを使わない処理でのレコード全体の返却を省く。削除件数は従来どおり削除前後の件数から求める。
- クローラーの一括保存はすでに `returning="minimal"` のため変更しない。

## 本番データの読み取り検証

数値は該当リクエスト本文のサンプル比較であり、HTTPヘッダー・圧縮・月間使用量の削減率ではない。

- 実際のPostgRESTクライアントと模擬HTTP応答で、JSON項目の選択、ページ分割、ランク補完後の再取得、空の保存応答を検証する。
