# ピック支援の503修正（2026-10-27）

## 原因と修正

`recommend_picks` は選択マップの `matchups` / `synergies` を利用するが、
`get_tier_list` の既定値によって、画面表示用の `kamo` / `tenteki` を補完する
全体相性まで取得していた。この追加RPCがPostgRESTの8秒制限に到達して503になった。

- 推薦APIでは `include_matchup_fallback=False` を明示する。選択マップの相性は従来どおり取得・利用する。
- 相性対象の履歴に `(mode, map_id, match_at DESC)` の部分インデックスを追加し、選択マップの検索で全履歴を走査しないようにする。
- 推薦スコアの式、相性値、対象ランク、60日間の期間、重複排除、時間減衰は変更しない。
- フロントエンドのピック支援はすでに補完取得を無効化しているため、画面側の変更は不要。

## 検証

本番データ・ブロストライカー / Beach Ballの測定:

| 検証 | 結果 |
| --- | --- |
| 修正前の補完ありAPI | 503、8.812秒 |
| 補完なしAPI | 200、1.594秒 |
| インデックス追加前のSQL実行計画 | 全履歴の並列Seq Scan、3,852.953ms |
| 追加後のSQL実行計画 | `idx_match_history_pair_context` を使用、345.441ms |
| 固定集計時刻での相性結果比較 | 50ペア、JSONのMD5が完全一致 |
| 追加インデックス | 12MB |

APIとEXPLAINの時間は異なる測定対象。単回測定であり、キャッシュ状態やDB負荷に依存する。
結果比較は両方で `2026-10-27T11:34:00Z` を使用し、ペアの順序を正規化した。

バックエンド回帰テスト118件成功。変更前から失敗する
`test_crawler_saves_battles_with_missing_map_or_brawler_name` は除外した。
追加テストは全体相性をタイムアウトさせた状態で推薦APIが200を返し、
選択マップの実際の敵・味方相性を使ったスコアが維持されることを検証する。
